# 项目协作入口

本文件是项目一级索引。处理任务时先读相关代码和契约，再按下表选读规范，不要一次加载整个 `.agents/` 目录。规范只约束本次改动，不要求顺手重写历史代码。

## 读取规则

- 沿路由表逐级选读：本文件 → 语言入口 → 编码索引 → 专题；审查时为审查协调 skill（轻量档为单人审查 skill）→ 职能 skill → 编码索引与专题。下游文件不要求返回上级。
- 当前上下文已包含且未变化的文件不重复读取；文件更新或上下文缺失时，只补读相关部分。
- 正文中指向契约、规划、记录或代码的链接只用于取证，不作为继续展开规范的指令。
- 分派子 agent 时，交接适用的上层约束原文及其来源（授权边界、推进门禁、角色职责）、候选专题路径和已包含的规范。下级按实际改动独立选择下游专题；缺失的上层约束由分派者补齐，下级不回读本文件。
- 读代码后发现需求已经满足，或与现有实现、契约冲突时，先向用户确认，不自行扩大或缩小范围。

## 独立审查

- 本项目审查档位为{{TIER}}档，各档位的职能组合见审查档位与严重度专题。
<!-- 条件: 轻量升档 -->
- 改动触及高风险区域时，本次审查按标准档执行；不确定是否触及时按触及处理。
<!-- /条件 -->
- 涉及可执行代码、测试、数据迁移或运行配置的改动，在实现和验证完成后、宣布完成或按用户要求提交前，按上表进行独立审查。发起前按审查交接专题把交接写入任务记录。
- 实现者不能审查自己的改动，也不能担任审查协调者；需要协调者时，由实现者启动一个独立 agent 或新的独立会话担任，交给它审查 skill 的路径和任务记录路径。实现者不需要阅读审查 skill。工具和会话都无法开启时，请用户开启新的会话担任。
- 只改业务文档或规范、不涉及可执行代码的改动，不需要完成前独立审查；拆分任务中的此类小任务仍按推进门禁审查。规范改动另按规范维护专题检查；业务文档改动核对与代码、契约的一致性，改动字段名、路径或接口语义时按涉及对外兼容处理。
- 审查结论只有三种：通过、有阻断问题、证据不足。证据不足、所需 agent 不可用或结论冲突时，不得声称审查通过。
- 审查者只读，不代替实现者修改代码；审查任务本身不再触发完成前审查。

## 拆分任务的推进门禁

用户要求拆分的任务，每个小任务按“实现及自检 → 独立审查”推进。独立审查发现阻断问题时，修复后交同一审查者复核，即原责任职能的原 agent 或原会话；无法恢复时按审查 skill 的规定移交替代者。

用户 review 的时机：{{GATE}}。到达用户 review 节点时，交付具体文件、验证结果和审查结论，把状态标为“待用户 review”并停止推进；用户确认通过后才标记“用户验收通过”并按授权继续。不能把沉默、经过的时间或 agent 的通过结论当作用户通过，也不能因收到下一项的启动指令而跳过前一项的独立审查和用户 review。

## 任务记录

- 需求确认后、开始实现前，实现者在 `.agents/agentRecord/` 建立本任务的记录文件，写入用户指令原文与授权，并登记到记录索引的列表。已有记录的持续任务在原文件中更新。涉及可执行代码、拆分任务或需要记录授权的任务必须建立记录；不属于拆分任务的单次纯文档修改可以不建。
- 任务拆分与规划、用户授权、阶段进度、交接内容、审查问题台账与结论、用户验收状态都写入该记录，格式见任务记录索引。规范、skill 和规划正文只保留通用规则和必要链接，不写入具体任务的进度或授权。
- 授权记录注明来源、日期、适用范围和有效状态；一次授权不扩展到其他任务；明确的当前用户指令优先。

## 提交与推送

完成改动并通过验证后，保留改动供用户检查。只有用户明确要求时才创建提交或推送。提交前检查提交内容，排除密钥、个人凭据、私有原始数据和生成文件；不得强制推送；远程分支已有新提交时，先核对并正常整合。
