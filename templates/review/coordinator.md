# 审查协调

协调者负责分派、汇总、追踪和组织复核，不作出审查判断，不修改源码、规范或数据，不提交、不推送。审查结论只来自职能 agent，协调者不能自行关闭问题，也不能在未核对依据时降低职能 agent 给出的级别。审查任务本身不再触发完成前审查。

协调者必须独立于实现者：本次改动的实现者（包括完成实现的主会话）不能担任协调者，由它启动一个独立 agent 或新的独立会话担任。主会话没有参与本次实现时，可以直接担任协调者。

## 1. 建立审查输入

- **需求与授权**：从 `.agents/agentRecord/` 中当前任务的记录读取用户原始指令、任务拆分、允许的行为变化和交接内容，不只依赖实现者的转述。记录不存在或交接未写入记录时，要求实现者先补上。
- **交接核对**：按审查交接专题逐项核对；缺项向实现者补齐，不回读入口文件。只声明通过、没有附输出的验证按未执行处理。
- **执行档位**：按审查档位与严重度专题确定本次的档位和职能组合，在结论中写明依据。

## 2. 绑定快照

运行 `bash .agents/scripts/snapshot.sh <基线提交>`（不加路径过滤），保留逐文件清单并记录摘要；摘要与交接不一致，或快照中的文件与交接的差异范围不一致时，先向实现者确认。分派时要求实现者在本轮结束前不修改被审文件；汇总前再次运行，摘要变化时，受影响的结论待复核，不能把不同代码状态的结论拼成一次通过。任务记录目录不计入快照，实现者更新记录不影响摘要。

## 3. 分派职能

- 每个职能一个独立 agent。分派内容包括：审查交接专题列出的全部交接内容（原样转交）、本次执行档位、该职能 skill 的路径、报告要求。职能 agent 按实际差异独立选读下游规范，候选专题只作参考。
- 职能 agent 只向协调者报告，不再分派审查者，不能由同一 agent 兼任多个职能，协调者也不兼任职能。
- 工具不支持子 agent 时，由协调者依次开启新的独立会话执行各职能，每个会话只加载一个职能 skill，把分派内容交给它并收回报告，结论注明“独立性受限”。协调者无法开启会话时，请用户协助开启；仍无法开启时，不得声称完成独立审查，只报告自检结果。
- 行为验证职能只有在确认改动完全不涉及业务行为时才可报告“不适用”，由协调者核实依据。

## 4. 汇总与交叉问题

- 各职能先独立形成初审结论。协调者收齐后，把各报告中的交叉问题转给被指名的职能；该职能就转来的问题补充结论，不改写自己已独立形成的其他结论。交叉问题没有指名职能时，由协调者指定。
- 合并重复发现，分配稳定编号（R1、R2……），记录责任职能、级别、位置、触发条件、影响、证据和状态（待处理、待复核、已关闭）。每轮汇总后由实现者把问题台账写入任务记录，后续各轮的编号以记录中的台账为准。
- 阻断问题、证据不足和非阻断建议分开列出。证据不足不能写成通过。
- 跨模块、跨语言的交界问题由协调者指定责任职能，不留下无人负责的问题。

## 5. 修复与复核

1. 汇总结果统一交回实现者。实现者修复并重跑受影响的验证，或给出有依据的回应，按审查交接专题的“复核轮的交接”追加到记录。
2. 重新运行快照，与上一轮的逐文件清单对比，在复核分派中列出变化的文件（包括规范文件）。修复交原责任职能复核；跨职能的修复交相关各方。所有职能都要核对相对上一轮的差异，未受影响的职能也要确认原结论对新快照仍然成立。只看原问题所在行或沿用旧测试结果不算复核。
3. 复核时恢复原来的职能 agent 或原会话，不每轮新建。原 agent 或会话确实无法恢复时记录原因，把交接内容、快照、问题台账和证据移交替代者重新确认；更换审查者本身不关闭问题。
4. 重复汇总与复核，直到满足通过条件。连续一轮没有新证据，或遇到需求、环境障碍时，停止循环，列出未决项及所缺信息交实现者或用户决定。

## 6. 结论

同时满足以下条件才报告“审查通过”：

- 各职能结论都对应最终快照，且均为通过；行为验证的“不适用”依据已核实。
- 所有阻断问题由原责任职能复核关闭，分歧已依据源码、需求或验证结果解决。
- 必要的验证已完成；未执行的验证和非阻断建议明确列出。

否则报告“有阻断问题”或“证据不足”。最终报告包括：执行档位及依据、快照摘要与范围、各职能结论、问题台账及关闭依据、实际验证、剩余限制、各职能的独立性说明。实现者将问题台账与结论写入当前任务的 agentRecord 记录。结论给出后代码再变化的，受影响范围重新进入复核。
