# 单人审查

由一个独立于实现者的审查者执行，不修改代码、文档或数据，不提交、不推送。实现者不能担任本审查者。审查任务本身不再触发完成前审查。

## 判断是否升档

先对照高风险区域表检查本次差异。触及或不确定是否触及时，停止本流程，告知实现者改用审查协调流程（路由见项目入口），不在本流程中继续；未触及时继续。

<!-- /条件 -->
## 审查输入

- 从 `.agents/agentRecord/` 中当前任务的记录读取用户原始指令、允许的行为变化和交接内容。记录不存在时，要求实现者先建立，不凭转述开始审查。
- 按审查交接专题核对交接内容。缺项向实现者补齐；只声明通过、没有附输出的验证按未执行处理。
- 记录快照：运行 `bash .agents/scripts/snapshot.sh <基线提交>`，不加路径过滤，并记录摘要。任务记录目录不计入快照，写入台账不会改变摘要。

## 依次审查

先按代码审查 skill 完成审查，再按行为验证 skill 完成验证，分别记录结论；两部分的报告要求以各自 skill 为准。阻断级别按严重度专题。

工具不支持独立子 agent 时，在新的独立会话中执行本流程，结论注明“独立性受限”；无法开启独立会话时，只能报告自检结果，不得声称完成独立审查。

## 修复与复核

问题使用稳定编号（R1、R2……），交回实现者修复。实现者返回逐项说明、新快照摘要和验证输出后，由同一审查者复核相对上一轮的完整差异。连续一轮没有新证据或遇到需求、环境障碍时，列出未决项交用户决定。

## 结论

代码审查和行为验证都通过（行为验证“不适用”须说明依据），且所有阻断问题已复核关闭、必要验证已完成时，报告“审查通过”；否则报告“有阻断问题”或“证据不足”。报告包括快照摘要、范围、两部分结论、问题台账及关闭依据、实际验证、剩余限制。实现者将问题台账与结论写入当前任务的 agentRecord 记录。
