# 单人审查

由一个独立于实现者的审查者执行，不修改代码、文档或数据，不提交、不推送。实现者不能担任本审查者。审查任务本身不再触发完成前审查。

## 判断是否升档

先对照高风险区域表检查本次差异。差异取自分派中给出的基线：任务记录和交接缺失时，用 `git diff <基线提交>` 和 `git status` 自行查看（后者用于发现未跟踪文件），不运行快照。两项都有问题时一并报告。触及或不确定是否触及时，停止本流程，向分派者报告“需升档”：写明触及的区域、不变量和依据差异，不给出审查结论，也不运行快照。分派者按项目入口改走审查协调流程；本审查者不转任协调者或职能 agent。未触及时继续。

“需升档”和“只报告缺少的文件”都不属于审查结论，须在报告中写明“本报告不是审查结论”，不得使用通过、有阻断问题、证据不足中的任何一个。

<!-- /条件 -->
## 审查输入

- 从 `.agents/agentRecord/` 中当前任务的记录读取用户原始指令和允许的行为变化；契约派发模式下另读本次契约文件，交接内容在契约的执行报告中。记录或交接不存在时，向分派者要求补上，不凭转述开始审查；补上前不开始审查，只报告缺少的文件，并写明本报告不是审查结论。
- 按审查交接专题核对交接内容。缺项向分派者要求补齐（直接执行模式下分派者就是实现者）；补齐前，依赖该项的结论报告为“证据不足”。只声明通过、没有附输出的验证按未执行处理。
- 记录快照：运行 `bash .agents/scripts/snapshot.sh <基线提交>`，不加路径过滤，并记录摘要。任务记录目录不计入快照，写入台账不会改变摘要。快照中的文件与交接的差异范围不一致时，向分派者确认，不自行选择一方。给出结论前再次运行，摘要变化时受影响的结论需要重新核对。

## 依次审查

先按代码审查 skill 完成审查，再按行为验证 skill 完成验证，分别记录结论；两部分的报告要求以各自 skill 为准，合并为一份报告。阻断级别按严重度专题。两个 skill 中“交分派者转给其他职能”的交叉问题，以及“由分派者核实”的不适用依据，在本流程中由本审查者自行处理并在报告中写明。单人审查依次执行两部分是本档位的设计，不因此注明“独立性受限”。

工具不支持独立子 agent 时，在新的独立会话中执行本流程，结论注明“独立性受限”；无法开启独立会话时，只能报告自检结果，不得声称完成独立审查。

## 修复与复核

问题使用稳定编号（R1、R2……），交回实现者修复。实现者返回逐项说明、新快照摘要和验证输出后，由同一审查者复核相对上一轮的完整差异。原审查者确实无法恢复时，记录原因，把交接、快照、问题台账和证据移交替代者重新确认；更换审查者本身不关闭问题。连续一轮没有新证据或遇到需求、环境障碍时，列出未决项，经分派者交用户决定；需要实现者补证据时，同时要求实现者补齐。

## 结论

代码审查和行为验证都通过（行为验证“不适用”须说明依据），且所有阻断问题已复核关闭、必要验证已完成时，报告“审查通过”；否则报告“有阻断问题”或“证据不足”。报告包括快照摘要、范围、实际读过的规范、两部分结论、问题台账及关闭依据、实际验证、剩余限制。Architect 将问题台账与结论写入当前任务的 agentRecord 记录。
