# 审查交接

实现者发起完成前独立审查时，把以下内容写入当前任务的 agentRecord 记录的“交接”一节，再交给审查方。审查协调者分派职能时，原样转交这些内容，并补充职能 skill 的路径和报告要求。职能 agent 和单人审查者按本页核对收到的交接。

## 交接内容

1. **需求与授权**：任务记录路径；用户原始指令原文；允许的行为变化（没有则写“无”）。
2. **差异范围**：已暂存、未暂存和未跟踪的文件清单；是否改动依赖清单。
3. **基线与快照**：基线提交（开始本任务实现时的提交；持续任务沿用首轮基线），及运行 `bash .agents/scripts/snapshot.sh <基线提交>`（不加路径过滤）得到的摘要。任务记录目录不计入快照，更新记录不会改变摘要。
4. **实际执行的验证**：命令及其输出摘要。未执行的验证写明原因；只声明通过、没有输出的，审查方按未执行处理。
5. **已知限制**。
6. **适用的上层约束**：授权边界、推进门禁、档位、角色职责。引用原文并注明出处，不只给行号。
7. **候选专题路径**：只作参考，审查方按实际差异独立选读。
8. **已读规范**：实现者已读的规范清单。

9. **新旧对照证据**：改动涉及旧实现时，按 [新旧实现对照](migration-comparison.md) 的“交付的证据”一节提供；不涉及时写“不适用”并说明理由。

## 复核轮的交接

每轮修复后，实现者在记录的“交接”一节追加一轮，不覆盖上一轮，内容包括：

1. 逐项处理说明：沿用问题编号，写明修复方式或有依据的回应。
2. 本轮新增或修改的文件，包括修复连带的其他改动。
3. 新的快照摘要。
4. 重跑的验证命令及输出。

协调者对比前后两轮快照的逐文件清单，在复核分派中列出自上一轮以来变化的文件，包括规范文件。职能 agent 只重读列出的规范文件；未列出的沿用上一轮。

## 缺项处理

- 实现者交接缺项时，协调者或单人审查者向实现者补齐后再分派或开始审查。
- 职能 agent 收到的分派缺项时，向协调者要求补齐，不回读入口文件自行查找；补齐前，依赖该项的结论报告为“证据不足”。
- 交接的差异范围与快照包含的文件不一致时，由协调者向实现者确认，统一后再分派。
