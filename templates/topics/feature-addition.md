# 新功能

适用于新增对外能力、后台流程、页面或数据字段。按实际触及的层执行，不要求每项功能修改所有层。

## 1. 确认行为与边界

- 写清使用者、入口、输入输出、成功与失败行为，以及已有行为是否变化。
- 找到相邻的实现和测试，核对相关的业务契约（另见 [业务契约](business-contracts.md)）。契约与现有代码不一致时，先查明现行行为和需求，再决定修改范围。
- 涉及权限、租户隔离、对外兼容接口、计费、任务状态、回调或部署时，写明相应的不变量和兼容边界。

## 2. 选定最小落点

- 在现有职责边界中选位置。只有新职责无法清楚归属时才新建模块。
- 明确输入校验与错误格式，区分管理接口、对外兼容接口和内部接口；新增校验不能意外收窄已有行为。
- 需要持久化时，先设计数据所有者、状态转换、事务、并发和旧数据兼容，再写迁移。
- 新增配置时说明默认值、生产环境要求和缺失配置时的行为；不提交真实凭据。

## 3. 实现与同步

- 小步实现完整的调用路径，复用现有的公共规则；按本任务已选定的专题编写，不返回上层索引重新展开。
- 只同步实际受影响的接口、架构和运维文档，不复制一份平行契约。
- 改变对外行为或数据结构时，说明兼容性、迁移顺序和回退条件。

## 4. 验证与交付

- 为关键的成功、边界、拒绝和失败路径补充测试。
- 交付说明包括：新增能力和入口、重要约束、迁移或配置要求、实际验证结果、尚未验证的风险。
