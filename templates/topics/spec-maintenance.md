# 规范维护

修改 `AGENTS.md`、`.agents/` 下的规范、skill 或任务记录模板时遵守本页。业务文档（如 `docs/`）不适用本页。

## 结构

- 层级：L0 `AGENTS.md` → L1 语言入口 → L2 编码索引与审查 skill → L3 专题。下游文件不写“先读上级入口”“返回索引”一类指令；需要上层约束时由分派者在交接中提供。
- 路由表固定两列：`| 任务或改动类型 | 按需阅读 |`，第二列只放链接及一句说明。路由链接只能指向同级或下级，整体不能成环。
- 正文中指向契约、规划、记录或代码的链接只用于取证，不作为阅读指令。专题之间需要互相提及时写 `另见 [文件](路径)`，计入路由。
- 索引文件只放路由表和必要约束，超过约 200 行时拆出下一级索引；专题只讲一个主题。
- 同一规则只在一个专题中定义，其他位置用链接引用。规范、skill 和规划正文不写具体任务的进度或授权，这些写入任务记录。

## 改动后的必做步骤

1. 新增、改名、移动或删除规范文件后，更新所有指向它的链接。
2. 运行 `python3 .agents/scripts/check_docs.py --update` 刷新层级映射。内容不变的改名或移动由脚本按 MD5 自动识别；改名的同时修改了内容、或新增文件时，脚本会列为未登记，用 `--set 路径 层级` 登记，层级定义见该脚本文件头。
3. 运行 `python3 .agents/scripts/check_docs.py`，要求没有错误；警告逐条判断。
4. `levels.json` 的变化与规范改动一起保留。

## 审查

不属于拆分任务的纯规范改动，通过上述检查即可交付，不需要独立审查。拆分任务中的规范小任务按项目入口的推进门禁执行独立审查。改动影响审查流程或角色职责时，在交付说明中列出受影响的角色和文件。
