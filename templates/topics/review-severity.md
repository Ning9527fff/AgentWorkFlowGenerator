# 审查档位与严重度

## 本项目的审查档位

<!-- 条件: 档位=轻量 -->
本项目为轻量档：由一个独立审查者依次完成代码审查和行为验证。风格问题只由格式化与 lint 工具检查。
<!-- /条件 -->
<!-- 条件: 档位=标准 -->
本项目为标准档：由审查协调者分派代码审查、行为验证两个职能。风格问题由工具检查，代码审查只能就明显妨碍理解的写法提 P3 建议。
<!-- /条件 -->
<!-- 条件: 档位=严格 -->
本项目为严格档：由审查协调者分派代码审查、风格审查、行为验证三个职能。风格审查可以把确实妨碍理解或维护的问题定为 P2。
<!-- /条件 -->
<!-- 条件: 轻量升档 -->

改动触及高风险区域时，本次审查按标准档执行：由审查协调者分派代码审查和行为验证两个职能。不确定是否触及时按触及处理。
<!-- /条件 -->

## 严重度

| 级别 | 含义 | 示例 |
| --- | --- | --- |
| P0 | 会造成数据损坏、资金错误、安全泄露或线上不可用 | 重复结算、越权访问、密钥写入日志 |
| P1 | 在常见路径上产生错误结果或违反对外契约 | 状态码或字段改变、事务边界错误、资源泄漏 |
| P2 | 在边界或异常路径上出错，或明显增加维护风险 | 异常分支丢失、测试未覆盖已改行为、职责严重混杂 |
| P3 | 不影响正确性的改进建议 | 命名可以更清楚、可以合并的重复代码 |

- 本项目的阻断级别：{{BLOCKING_LEVELS}}。P3 不阻断，单独列为建议。
- 风格问题最高定为 P2，只有在严格档且确实妨碍理解或维护时才定为 P2；其他档位的风格问题定为 P3。工具能检查的问题不进入人工审查结论。
- 定级时说明触发条件与影响。协调者不得在未核对依据的情况下降低职能 agent 给出的级别。
- 问题是否成立取决于尚未提供的证据（如源码、命令输出）时，列入“证据不足”，并写明证据补齐后可能的级别，不在此前定级。
