# 代码提交

仅在用户明确要求创建提交或推送时使用。

## 提交范围

- 一个提交围绕一个可说明、可审阅的目的，包含实现该目的所需的代码、测试、迁移和文档。相互独立的修复或重构分开提交。
- 不拆出会让中间提交无法构建或破坏现有行为的碎片；数据迁移与依赖它的代码按兼容顺序组织。
- 保留工作区中与本次任务无关的改动。暂存时明确选择文件或片段，不默认暂存全部文件。

## 提交前检查

- 查看工作区状态和已暂存差异，确认暂存内容、删除的文件、生成文件和意外的格式化改动都符合本次目的。
- 检查是否误纳入密钥、令牌、私有数据、临时文件、缓存或大型构建产物；示例配置只用占位值。
- 运行与改动风险相称的验证并记录实际结果。验证失败时先修复，或在交付说明中写明失败原因与影响。
- 确认文档、迁移、依赖锁文件和测试与行为变更同步。

## 提交说明

- 标题用一句话说明实际变化，不用“update”“fix bug”“调整代码”一类无法定位内容的表述。
- 沿用仓库已有的提交格式；仓库没有稳定格式时不强制前缀。
- 复杂或有风险的提交，在正文写明原因、重要的行为变化、迁移或兼容影响和验证情况。
- 不声称未执行的测试或未完成的上线结果。

## 提交后

- 检查提交包含预期文件、工作区剩余改动属于预期，向用户说明提交标识、主要变化和仍需处理的事项。
- 推送前核实目标分支和远程状态；不强制推送；远程已有新提交时先核对并正常整合。
